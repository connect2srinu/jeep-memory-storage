When a schema changes

New versions only add. Approvals keep working.

KSA · version 1

organic_brand · dietary_restriction · …

KSA · version 2

everything in v1 + preferred_size (new)

Nothing is removed or renamed — existing preferences and values carry over.

Approved access carries over — Cooklist's grant on organic_brand still works on v2.

New preferences are not shared automatically — preferred_size needs a new approval.

A new schema version can only add preferences, so nothing that other agents depend on disappears under them. Because approvals list individual preferences, a new field is never quietly handed to other agents; they have to ask. That's also why a breaking change, like removing a field, isn't possible in this flow today.
